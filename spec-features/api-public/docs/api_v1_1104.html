Loại tài liệu: Đặc tả chi tiết API

Đặc tả chi tiết API Phase 1 liên kết ngoài của LME

Bản tiếng Việt để xác nhận phạm vi public API Phase 1 trước khi bước vào spec chi tiết.

Tài liệu này đóng gói từng API theo format: mục đích, endpoint, Input parameter, Output parameter, Sample Input và Sample Output.

1

Mục đích

Kết luận

Phase 1 cần định nghĩa trước các API để hệ thống bên ngoài đưa kết quả phán đoán quay lại LME.

Phạm vi gồm lấy danh sách/chi tiết friend, add/remove tag, cập nhật friend info, start/stop scenario, gửi message, lấy template và lấy conversation.

Tài liệu này quyết gì

Xác định endpoint public API và parameter chính của từng API.

Tên API được sắp xếp lại cho bên ngoài, không giả định public nguyên tên hàm MCP nội bộ.

Nguồn tham chiếu

Tham chiếu MCP hệ thống LME để phản ánh ID, giới hạn và action type đang có.

URL, authentication signature và retry spec sẽ xác định ở spec chi tiết. Rate limit đã chốt ở mục 2.

2

Quy định chung

Các API dùng chung authentication, paging, idempotency và error format.

Hạng mụcĐề xuấtGhi chú
Base URLStaging: https://api-stg.lmes.jp
Production: https://api.lmes.jp		Mọi endpoint đều nằm dưới prefix /v1 (ví dụ https://api.lmes.jp/v1/friends).
AuthenticationX-LME-API-KEYAPI key gốc lme_live_sk_<32hex> (#40041), cấp theo bot. Server tra api_keys.key_lookup_hash = HMAC-SHA256(key, API_KEY_PEPPER); từ key suy ra bot + quyền scope full/read; kiểm tra is_deleted, status, expires_at (null = vĩnh viễn).
Request formatContent-Type: application/jsonAPI lấy danh sách dùng query. API cập nhật dùng JSON body.
Ngày giờYYYY-MM-DD, YYYY-MM-DDTHH:mm:ss+09:00Event, reservation và payment dùng giờ Nhật làm chuẩn.
Pagingpage, limitlimit mặc định 100 record, tối đa 500 record.
Rate limitĐọc (GET): 300 request/phút
Ghi (POST/PUT/DELETE): 60 request/phút		Quota tính theo bot, cửa sổ cố định theo phút (fixed window, reset mỗi đầu phút). Mọi response /v1 kèm header X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset. Vượt ngưỡng → 429 rate_limited + header Retry-After (giây). Chỉ đếm request đã xác thực API key.
IdempotencyIdempotency-KeyDùng cho /do_action, /messages/push, /messages/template để tránh chạy trùng. Giá trị do người dùng tự đặt, độ dài tối đa 100 ký tự (vượt → 400 invalid_request).
Key đối chiếulmessage_friend_id, line_friend_idDùng L Message Friend ID hoặc LINE Friend ID.

GET/friends

Lấy danh sách friend

Dùng khi CRM đồng bộ lần đầu hoặc cập nhật danh sách friend trong LME theo paging và filter cơ bản.

Input parameter

ParameterVị tríBắt buộcTypeMô tả
pagequeryKhôngintegerSố trang cần lấy. Mặc định là 1.
limitqueryKhôngintegerSố record lấy. Mặc định 100, tối đa 500.
line_namesqueryKhôngstring | CSVTìm gần đúng theo tên LINE hoặc tên quản lý trong LME (không phân biệt hoa thường). Nhiều giá trị → OR.
tag_idsqueryKhônginteger | CSVTag ID cần lọc (lấy từ /tags). Nhiều giá trị → OR (friend có ít nhất 1 tag).
emailsqueryKhôngstring | CSVEmail cần lọc, khớp chính xác. Nhiều giá trị → OR.
added_date_fromqueryKhôngdateNgày thêm bạn từ ngày, format YYYY-MM-DD.
added_date_toqueryKhôngdateNgày thêm bạn đến ngày, format YYYY-MM-DD.

Các filter khác nhau kết hợp theo điều kiện AND; nhiều giá trị trong cùng một filter (phân tách bằng dấu phẩy hoặc lặp param) kết hợp theo OR.

POST/messages/push

Gửi message (text / media)

Gửi message cho LINE friend chỉ định. API này thay thế /messages/text và /messages/media: mảng messages[] chứa cả text và media (chỉ hỗ trợ image, video, audio), gửi theo thứ tự khai báo.

Giới hạn

Hạng mụcGiới hạn
Message objects trong một requestTối đa 5
TextTối đa 5.000 ký tự/object
URL mediaTối đa 2.000 ký tự, HTTPS TLS 1.2+
Ảnh gốcJPEG/PNG, tối đa 10 MB
Ảnh previewJPEG/PNG, tối đa 1 MB
VideoMP4, tối đa 200 MB
AudioMP3/M4A, tối đa 200 MB

Input parameter

ParameterVị tríBắt buộcTypeMô tả
friend_idbodyCóinteger|stringFriend ID nhận message.
id_typebodyKhôngstringlmessage_friend_id hoặc line_friend_id. Mặc định là lmessage_friend_id.

Lịch sử cập nhật

Bản mới nhất luôn ở trên cùng. Khi trao đổi về tài liệu này, vui lòng nêu rõ số bản để tránh nhầm giữa các lần cập nhật.

BảnNgàyNội dung thay đổi
1.2.028/09/2026① Bổ sung bảng đầy đủ built-in friend info field (ID âm) ở GET /friend-info-fields: -1..-4, -6..-10 (field_id, tên, field_type); Sample Output liệt kê đủ các field mặc định.
② Built-in field -6 (都道府県名 / tỉnh thành) là SELECT với 47 option cố định: GET /friend-info-fields nay trả options[] đủ 47 tỉnh với option_id = STT 1-based (1=北海道 … 13=東京都 … 47=沖縄県). POST /do_action action friend_info.set field -6 nhận option_id (server resolve STT → tên tỉnh string rồi lưu; ngoài 1..47 → 404; gửi value thay option_id → 422). Khi đọc ra (/friends/detail) value là tên tỉnh string.
1.1.021/09/2026① Resource thuộc bot khác trả 404 not_found (trước đây 403/422).
② Đổi "compliant status" → "handling status": path /handling-statuses, field data.handling_status của GET /conversations/detail.
③ Đổi path: GET /conversations (message gần nhất của friend) → GET /conversations/detail. API mới GET /conversations — lấy danh sách conversation, filter theo trạng thái đã đọc (confirm_status) và trạng thái xử lý (handling_status_ids).
④ POST /do_action: thêm action type confirm_status (confirm / unconfirm) để đổi trạng thái đã đọc/chưa đọc của conversation.
⑤ Bỏ tiền tố filters. ở query param của GET /conversations và GET /friends. GET /conversations dùng tên param giống MCP (handling_status_ids, line_names, tag_ids, tag_names…); GET /friends: bỏ filters.type (các filter kết hợp AND); thêm line_names (tìm theo tên LINE hoặc tên quản lý, giống GET /conversations); tag_id → tag_ids, email → emails (nhận nhiều giá trị).
⑥ Tên friend thống nhất với GET /friends: GET /conversations tách line_name (tên LINE) và system_name (tên quản lý) — trước đây gộp dạng tên quản lý (tên LINE); GET /friends/detail thêm system_name.
1.0.010/09/2026Bản đầu tiên.

Tài liệu này là bản tiếng Việt để xác nhận hướng API detail spec. Authentication signature, retry spec và data type cuối cùng sẽ xác định ở spec chi tiết. Base URL và rate limit đã chốt ở mục 2 (300 đọc / 60 ghi mỗi phút, theo bot).
